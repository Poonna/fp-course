Functions that call themselves

A definition in terms of itself

5! = 5 \times \underbrace{4 \times 3 \times 2 \times 1}_{4!} = 5 \times 4!

n! = \begin{cases} 1 & \text{if } n = 0 \\ n \times (n-1)! & \text{if } n > 0 \end{cases}

How would you write this in F#, with what you know from Week 1?

let rec factIf n =
    if n = 0 then 1
    else n * factIf (n - 1)

rec is required

> let fact n = if n = 0 then 1 else n * fact (n - 1);;

error FS0039: The value or constructor 'fact' is not defined.

Without rec, the name isn’t bound yet inside its own body.

Tracing factIf 3

factIf 3 = 3 * factIf 2
         = 3 * (2 * factIf 1)
         = 3 * (2 * (1 * factIf 0))
         = 3 * (2 * (1 * 1))
         = 3 * (2 * 1)
         = 3 * 2
         = 6

The expression grows, then shrinks. The multiplications wait, kept on the call stack (Week 7).

Point at the widest line: three multiplications waiting. Ask: where does the computer keep them?

A recipe

Four steps, every time

  1. Type — what goes in, what comes out
  2. Base case — the input so small the answer is obvious
  3. Recursive case — assume it works for a smaller input; build from that
  4. Check — trace a small input; does every call get closer to the base case?

Step 3 feels like cheating. Trust the smaller call, the way you trust sqrt.

The recipe on sumTo

Add up 1 + 2 + … + n.

  1. Type — int -> int
  1. Base case — sumTo 0 = 0
  1. Recursive case — if sumTo (n - 1) is right, then sumTo n = n + sumTo (n - 1)
  1. Check — sumTo 3 = 3 + (2 + (1 + 0)) = 6; each call subtracts 1
let rec sumToIf n =
    if n = 0 then 0
    else n + sumToIf (n - 1)

Another way: match

The math, and the code

The definition, written as cases:

\begin{aligned} 0! &= 1 \\ n! &= n \times (n-1)! \end{aligned}

F# can say exactly this:

let rec fact n =
    match n with
    | 0 -> 1
    | n -> n * fact (n - 1)

The definition you write on paper, typed in almost as it is.

How match works

let rec fact n =
    match n with
    | 0 -> 1
    | n -> n * fact (n - 1)
  • each | pattern -> expression is a rule
  • rules are tried top to bottom; the first that fits wins
  • a name pattern (n) fits anything, and binds the value

Rule 7: evaluate the value; try patterns in order; bind names; continue with that rule.

Kinds of patterns

Pattern Example Matches
constant 0, "Sunday" only that value
name n, day anything, and binds it
wildcard _ anything, binds nothing
or "Saturday" | "Sunday" either one 
let isWeekend' day =
    match day with
    | "Saturday" | "Sunday" -> true
    | _ -> false

Guards: a condition on a rule

sign n should be -1, 0, or 1. But “all positive numbers” is not one value…

let sign n =
    match n with
    | 0 -> 0
    | n when n > 0 -> 1     // guard: only if n > 0
    | _ -> -1

The rule applies only if the pattern fits and the guard is true.

The compiler checks your cases

> let describe n =
      match n with
      | 0 -> "zero"
      | 1 -> "one";;

warning FS0025: Incomplete pattern matches on this expression.
For example, the value '2' may indicate a case not covered.
> let rec bad n =
      match n with
      | n -> n * bad (n - 1)
      | 0 -> 1;;

warning FS0026: This rule will never be matched

Rewrite with match

let absolute n = if n < 0 then -n else n
let absolute n =
    match n with
    | n when n < 0 -> -n
    | n -> n

The recursion ladder

Problem: powers

Compute x^n, for a float x and a natural number n.

  • power 2.0 3 = 8.0
  • power 1.5 2 = 2.25

Your turn. Type? Base case? Recursive case? Check?

Give 2–3 minutes, in pairs if possible. Collect the type first, then the base case. Resist showing the next slide until someone proposes the recursive case.

power: the recipe

  1. Type — float -> int -> float
  2. Base case — x^0 = 1
  3. Recursive case — x^n = x \times x^{n-1}
  4. Check — power 2.0 3 = 2.0 * (2.0 * (2.0 * 1.0)) = 8.0
let rec power x n =
    match n with
    | 0 -> 1.0
    | n -> x * power x (n - 1)

Two parameters, but only n shrinks; x is passed along unchanged.

Problem: repeating text

Repeat a string n times.

  • repeat "ab" 3 = "ababab"
  • repeat "ab" 0 = ""

Your turn. Type? Base case? Recursive case? Check?

The base case is the interesting question: what is “zero copies” of a string?

repeat: the recipe

  1. Type — string -> int -> string
  2. Base case — zero copies is the empty string ""
  3. Recursive case — one copy of s, followed by n - 1 copies
  4. Check — repeat "ab" 2 = "ab" + ("ab" + "") = "abab"
let rec repeat s n =
    match n with
    | 0 -> ""
    | n -> s + repeat s (n - 1)

Recursion isn’t only arithmetic: anything built piece by piece.

Problem: binary digits

Write a natural number in base 2, as a string.

  • binary 6 = "110"
  • binary 13 = "1101"

Your turn. Type? Base case? Recursive case? Check?

Hint: the last binary digit of n is n % 2. What are the digits before it?

Show the hint only if the room is stuck after a couple of minutes. Many students will find one base case (0); leave the second for the next slides.

binary: the recipe

  1. Type — int -> string
  2. Base cases — 0 is "0", and 1 is "1"
  3. Recursive case — the digits of n / 2, then the last digit n % 2
  4. Check — binary 6 = binary 3 + "0" = (binary 1 + "1") + "0" = "110"
let rec binary n =
    match n with
    | 0 -> "0"
    | 1 -> "1"
    | n -> binary (n / 2) + string (n % 2)

“Smaller” here means halving, not subtracting 1.

Predict: one base case only

With only | 0 -> "0" as the base case, what is binary 6?

binary 6 = binary 3 + "0"
         = (binary 1 + "1") + "0"
         = ((binary 0 + "1") + "1") + "0"
         = "0110"

A leading zero. That is why binary needs two base cases.

Problem: adding up digits

Add up the decimal digits of a natural number.

  • digitSum 1234 = 1 + 2 + 3 + 4 = 10
  • digitSum 7 = 7

Your turn. Type? Base case? Recursive case? Check?

Hint: n % 10 is the last digit; n / 10 is the number without it.

Watch for the base case: most students first write | 0 -> 0, which also works. Ask whether a one-digit base case is more natural, and how to write “any number below 10” as a pattern (guard).

digitSum: the recipe

  1. Type — int -> int
  2. Base case — a number below 10 is its own digit sum: a range, so a guard
  3. Recursive case — the last digit, plus the digit sum of the rest
  4. Check — digitSum 1234 = 4 + (3 + (2 + 1)) = 10: each call removes one digit
let rec digitSum n =
    match n with
    | n when n < 10 -> n
    | n -> n % 10 + digitSum (n / 10)

Problem: greatest common divisor

The largest number that divides both a and b.

  • gcd 48 18 = 6
  • gcd 17 5 = 1

Euclid’s fact (around 300 BC): \gcd(a, b) = \gcd(b,\ a \bmod b)

Your turn. With that fact, what is the base case? Write it.

Euclid’s fact is given, since it’s number theory rather than programming. The programming question is the base case: what happens when b reaches 0?

gcd: the recipe

  1. Type — int -> int -> int
  2. Base case — \gcd(a, 0) = a: everything divides 0
  3. Recursive case — Euclid’s fact
  4. Check — the second argument shrinks: a % b is always less than b
let rec gcd a b =
    match b with
    | 0 -> a
    | b -> gcd b (a % b)
gcd 48 18 = gcd 18 12 = gcd 12 6 = gcd 6 0 = 6

gcd vs fact

fact 3 = 3 * (2 * (1 * fact 0))       work waits: the expression grows

gcd 48 18 = gcd 18 12 = gcd 12 6      nothing waits: it never grows

Remember this difference. It becomes important in Week 7.

Problem: Fibonacci numbers

0, 1, 1, 2, 3, 5, 8, 13, 21, …: each is the sum of the two before it.

  • fib 0 = 0, fib 1 = 1
  • fib 10 = 55

Your turn. Type? Base case(s)? Recursive case?

fib: the recipe

  1. Type — int -> int
  2. Base cases — fib 0 = 0 and fib 1 = 1: two, because the recursive case looks two steps back
  3. Recursive case — fib n = fib (n - 1) + fib (n - 2): two recursive calls
  4. Check — fib 4 = fib 3 + fib 2 = (fib 2 + fib 1) + (fib 1 + fib 0) = … = 3
let rec fib n =
    match n with
    | 0 -> 0
    | 1 -> 1
    | n -> fib (n - 1) + fib (n - 2)

It reads exactly like the definition.

Is fib fast?

Your turn. How long will fib 40 take? And fib 42?

> fib 40;;
Real: 00:00:01.002 ...
> fib 42;;
Real: 00:00:02.254 ...

About ×1.6 per step: the same values are computed over and over. Correct, but a bad program.

Before revealing the timings, ask for guesses: how long will fib 40 take? Then ask why it’s slow; drill A7 draws the call tree.

When recursion goes wrong

No way to the base case

What does fact (-1) do?

It counts down forever: -1, -2, -3, …

Stack overflow.
Repeated 261720 times:
   at FSI_0001.fact(Int32)

Same crash if the call doesn’t shrink (fact n), or the base case is unreachable (FS0026).

let rec factSafe n =
    match n with
    | n when n < 0 -> failwith "factSafe: negative input"
    | 0 -> 1
    | n -> n * factSafe (n - 1)

Numbers that are too big

> fact 12;;
val it: int = 479001600

> fact 13;;
val it: int = 1932053504

Is this right?

13! = 6{,}227{,}020{,}800, but int stops at about 2.1 \times 10^9 and wraps silently.

Use int64 (literals 20L) or bigint (literals 20I).

Find the bug

let rec repeat s n =
    match n with
    | 0 -> s
    | n -> s + repeat s (n - 1)

repeat "ab" 2 gives "ababab": an off-by-one, with no warning at all.

Step 4 of the recipe, tracing a small input, is what catches it.

Reading types

Many arrows

> let add x y = x + y;;
val add: x: int -> y: int -> int

Arrows group to the right: int -> (int -> int)

Give it one argument, get a function back:

let add x y = x + y
let add5 = add 5              // a function still waiting for y
let eight = add5 3

Application groups to the left: add 5 3 = (add 5) 3. This is currying.

Partial application

let twoTo = power 2.0         // int -> float: powers of two
let kilo = twoTo 10           // 1024.0
let say = printfn "Hello, %s!"   // string -> unit

The Week 1 promise: printfn "…%s…" is a function waiting for a string, checked at compile time.

Order matters: put the “setting” parameters first, the data last.

Generic types

let identity x = x
let first x y = x
let alwaysZero _ = 0
val identity: x: 'a -> 'a
val first: x: 'a -> y: 'b -> 'a
val alwaysZero: 'a -> int

'a means any type. And 'a -> 'a knows nothing about its argument, so it can only hand it back.

Functions as parameters

let twice f x = f (f x)
let plus2 = twice (add 1)
val twice: f: ('a -> 'a) -> x: 'a -> 'a

Parentheses in a type: a parameter that is itself a function. More in Week 5.

Working out a type by hand

  1. Unknowns — a placeholder for each parameter and the result
  2. Clues — each use of a parameter says something
  3. Combine — disagreeing clues are a type error
  4. Generalise — no clues at all? It stays 'a

let pick x y = if x > 0 then y + 1 else y * 2

  • x > 0: x is int
  • y + 1: y is int, and so is the result

pick: x: int -> y: int -> int

When F# needs help

let squareF (x: float) = x * x
let cube x : float = x * x * x      // annotate the result instead
> let len s = s.Length;;
error FS0072: Lookup on object of indeterminate type ...
let shout (s: string) = s.ToUpper() + "!"

Read the type

  1. let g x y = x * y + 0.5
  2. let h a b = if a then b else b + 1
  3. let pairUp x y = y
  4. let apply f x = f x
  1. float -> float -> float
  2. bool -> int -> int
  3. 'a -> 'b -> 'b
  4. ('a -> 'b) -> 'a -> 'b

Beyond F#

Pattern matching everywhere

Language Factorial by cases
Haskell fact 0 = 1 / fact n = n * fact (n - 1)
Rust match n { 0 => 1, n => n * fact(n - 1) }
Kotlin when (n) { 0 -> 1; else -> n * fact(n - 1) }
C# n switch { 0 => 1, _ => n * Fact(n - 1) }
Python 3.10+ match n: / case 0: / case _:
  • Many languages limit recursion depth (Python: about 1000 calls)
  • Currying elsewhere: const add = x => y => x + y;
  • Most languages infer local types; F# infers parameter types too

Summary

  • Recursion: let rec, a base case, and a smaller call
  • Recipe: type, base, recursive (trust it), check
  • match: rules tried top to bottom; the code mirrors the equations
  • Watch for stack overflow and silent int overflow
  • a -> b -> c = a -> (b -> c): partial application
  • 'a: generic; annotate when the clues run out
