Functions, Recursion, and Reading Types

Recursion becomes easy only through repetition, so this sheet is long on purpose. Each section has three tiers:

  • Core: everyone does these. We do some of them in class.
  • Practice: more of the same shape. Do these until the recipe feels automatic.
  • Stretch: harder variations, for when the core feels easy.

Work on paper first, then check in FSI. For every function you write, go through the four steps of the recipe: type, base case, recursive case, check.

Unless a question says otherwise, use these definitions from the notes:

let rec sumTo n =
    match n with
    | 0 -> 0
    | n -> n + sumTo (n - 1)

let rec power x n =
    match n with
    | 0 -> 1.0
    | n -> x * power x (n - 1)

let rec repeat s n =
    match n with
    | 0 -> ""
    | n -> s + repeat s (n - 1)

let rec binary n =
    match n with
    | 0 -> "0"
    | 1 -> "1"
    | n -> binary (n / 2) + string (n % 2)

let rec digitSum n =
    match n with
    | n when n < 10 -> n
    | n -> n % 10 + digitSum (n / 10)

let rec gcd a b =
    match b with
    | 0 -> a
    | b -> gcd b (a % b)

let rec fib n =
    match n with
    | 0 -> 0
    | 1 -> 1
    | n -> fib (n - 1) + fib (n - 2)

let add x y = x + y
let twice f x = f (f x)

A. Trace by hand

Write the evaluation step by step until you reach a value. For Core, write a full trace, numbering each step with the rule you used (including rule 7 for match), for at least A1. For the others, the equation style (sumTo 3 = 3 + sumTo 2 = …) is enough.

Core

  1. sumTo 4 (full trace)
  2. power 3.0 2
  3. binary 13
  4. gcd 84 36. How many calls to gcd happen in total?

Practice

  1. repeat "-" 3
  2. digitSum 9075

Stretch

  1. Draw all the calls made by fib 5 as a tree, with fib 5 at the top and each call’s children below it. How many calls are there in total? How many times is fib 3 computed? Why does this explain the slowness of fib 40?
TipAnswers 
1.   sumTo 4
   ⇝ match 4 with | 0 -> 0 | n -> n + sumTo (n - 1)     (3)
   ⇝ 4 + sumTo (4 - 1)                                  (7) 4 isn't 0; n ↦ 4
   ⇝ 4 + sumTo 3                                        (4)
   ⇝ 4 + (3 + sumTo 2)                                  (3),(7),(4)
   ⇝ 4 + (3 + (2 + sumTo 1))                            (3),(7),(4)
   ⇝ 4 + (3 + (2 + (1 + sumTo 0)))                      (3),(7),(4)
   ⇝ 4 + (3 + (2 + (1 + 0)))                            (3),(7) 0 fits
   ⇝ 4 + (3 + (2 + 1))  ⇝  4 + (3 + 3)  ⇝  4 + 6  ⇝  10  (4)

2.   power 3.0 2 = 3.0 * power 3.0 1
                 = 3.0 * (3.0 * power 3.0 0)
                 = 3.0 * (3.0 * 1.0)
                 = 9.0

3.   binary 13 = binary 6 + "1"                 13 = 2 × 6 + 1
               = (binary 3 + "0") + "1"         6 = 2 × 3 + 0
               = ((binary 1 + "1") + "0") + "1" 3 = 2 × 1 + 1
               = "1" + "1" + "0" + "1"
               = "1101"

4.   gcd 84 36 = gcd 36 12       84 % 36 = 12
               = gcd 12 0        36 % 12 = 0
               = 12              three calls in total

5.   repeat "-" 3 = "-" + ("-" + ("-" + "")) = "---"

6.   digitSum 9075 = 5 + digitSum 907
                   = 5 + (7 + digitSum 90)
                   = 5 + (7 + (0 + digitSum 9))
                   = 5 + (7 + (0 + 9))
                   = 21
  1. The tree has 15 calls. fib 3 is computed twice, fib 2 three times, fib 1 five times. Every call to fib n (for n ≥ 2) makes two more calls, and the two subtrees overlap almost completely, so the number of calls grows about as fast as the Fibonacci numbers themselves: roughly ×1.6 for each step. fib 40 makes over 300 million calls.

B. From equations to F

Each function is given as equations. Write it in F# with match, and give its type.

Core

  1. The sum of the squares 0^2 + 1^2 + \cdots + n^2: \mathit{sq}(0) = 0 \qquad \mathit{sq}(n) = n^2 + \mathit{sq}(n-1) sumOfSquares 3 should be 14.
  2. A rocket countdown: countdown 3 should be "3 2 1 liftoff". \mathit{cd}(0) = \text{"liftoff"} \qquad \mathit{cd}(n) = n \text{ followed by a space and } \mathit{cd}(n-1)
  3. Multiplication by repeated addition (no * allowed): a \cdot 0 = 0 \qquad a \cdot b = a + a \cdot (b - 1)

Practice

  1. numDigits: the number of decimal digits of a natural number. numDigits 9075 = 4, numDigits 7 = 1. Hint: look at digitSum, and write the equations first.
  2. Tower of Hanoi. Moving a stack of n discs takes h(n) moves, where h(0) = 0 \qquad h(n) = 2\,h(n-1) + 1 Write hanoi, and compute hanoi 10. Can you guess a formula for hanoi n?

Stretch

  1. Generalise binary to any base from 2 to 10: toBase 8 64 = "100", toBase 10 1234 = "1234". Which order should the parameters be in, so that let octal = toBase 8 works?
  2. The Ackermann function is a famous example of a function that grows extremely fast: A(0, n) = n + 1 \qquad A(m, 0) = A(m - 1, 1) \qquad A(m, n) = A(m - 1,\ A(m, n - 1)) Write ack m n. You will need a match inside a match. Check that ack 2 3 = 9 and ack 3 3 = 61. Don’t try ack 4 2: the answer has 19,729 digits.
TipAnswers 
let rec sumOfSquares n =
    match n with
    | 0 -> 0
    | n -> n * n + sumOfSquares (n - 1)

let rec countdown n =
    match n with
    | 0 -> "liftoff"
    | n -> string n + " " + countdown (n - 1)

let rec mul a b =
    match b with
    | 0 -> 0
    | b -> a + mul a (b - 1)

Types: sumOfSquares: int -> int, countdown: int -> string, mul: int -> int -> int.

let rec numDigits n =
    match n with
    | n when n < 10 -> 1
    | n -> 1 + numDigits (n / 10)

let rec hanoi n =
    match n with
    | 0 -> 0
    | n -> 2 * hanoi (n - 1) + 1

hanoi 10 = 1023. The formula is h(n) = 2^n - 1 (you can prove it by induction, as in the notes).

let digitChar d = string d        // digits 0-9 only, enough for bases up to 10

let rec toBase b n =
    match n with
    | n when n < b -> digitChar n
    | n -> toBase b (n / b) + digitChar (n % b)

let octal = toBase 8

let rec ack m n =
    match m with
    | 0 -> n + 1
    | m ->
        match n with
        | 0 -> ack (m - 1) 1
        | n -> ack (m - 1) (ack m (n - 1))

The base must come first, so that partial application fixes it: toBase 8 is a function waiting for the number. Notice how toBase is binary with 2 replaced by b, and how the base case is a range (n < b) instead of two constants.

C. if and match

Core

  1. Rewrite with match and a guard:

    let absolute n = if n < 0 then -n else n

  2. Rewrite Week 1’s shippingFee using match with guards instead of if/elif:

    let shippingFee weight =
    if weight <= 1 then 40
    elif weight <= 5 then 40 + (weight - 1) * 15
    else 100 + (weight - 5) * 10

Practice

  1. Now the other direction. Rewrite isWeekend from the notes without match and without if, as a single boolean expression.

Stretch

  1. For each of the three functions above, which version do you find clearer, and why? Is there a general rule?
TipAnswers 
let absolute n =
    match n with
    | n when n < 0 -> -n
    | n -> n

let shippingFee weight =
    match weight with
    | w when w <= 1 -> 40
    | w when w <= 5 -> 40 + (w - 1) * 15
    | w -> 100 + (w - 5) * 10

let isWeekendIf day = day = "Saturday" || day = "Sunday"
  1. There is no single right answer. A reasonable rule: when the cases are ranges of one value (as in shippingFee), match with guards and if/elif are about equally clear. When the cases are specific values, match is clearer. When the answer is itself a yes/no, a boolean expression is often simplest. From Week 4 on, match wins almost every time, because it can take apart structured values.

D. Find the bug

Each function is wrong. Say what happens when you use it (error, warning, wrong answer, or crash), and fix it.

Core

  1. let rec sumTo n =
    match n with
    | 0 -> 0
    | n -> n + sumTo n
  2. let fact n =
    match n with
    | 0 -> 1
    | n -> n * fact (n - 1)
  3. let rec fact n =
    match n with
    | n -> n * fact (n - 1)
    | 0 -> 1
  4. let rec repeat s n =
    match n with
    | 0 -> s
    | n -> s + repeat s (n - 1)

Practice

  1. What does binary 6 give with this version? Why?

    let rec binary n =
    match n with
    | 0 -> "0"
    | n -> binary (n / 2) + string (n % 2)

  2. This works for some inputs and crashes on others. Which ones?

    let rec countdown n =
    match n with
    | 0 -> "liftoff"
    | n -> string n + " " + countdown (n - 2)

Stretch

  1. fact 13 returns 1932053504. Is that correct? What happened, and how do you fix it?
TipAnswers
  1. The recursive call sumTo n doesn’t make the input smaller, so it never reaches 0: stack overflow for any input except 0. Fix: sumTo (n - 1).
  2. Missing rec: error FS0039, The value or constructor 'fact' is not defined.
  3. The first rule catches everything, so the base case is never used: warning FS0026, This rule will never be matched, and then a stack overflow at run time. Fix: put | 0 -> 1 first.
  4. Wrong base case: repeating s zero times should give "", not s. Now repeat "ab" 2 gives "ababab", one copy too many. An off-by-one error with no warning at all. The check step (trace a small input!) catches it.
  5. "0110", with a leading zero. binary 1 = binary 0 + "1" = "01", and that extra "0" appears at the front of every result. The fix is the second base case | 1 -> "1".
  6. It subtracts 2, so it only reaches 0 from even numbers. countdown 4 = "4 2 liftoff" works, but countdown 3 goes 3, 1, -1, -3, …: stack overflow. The measure (the notes’ “going further” box) doesn’t reach the base case.
  7. Not correct: 13! = 6{,}227{,}020{,}800, which is bigger than the largest int (about 2.1 billion). int arithmetic wraps around silently. Fix: use int64 (factBig 13L in the notes) or bigint.

E. Read the type

Write the type FSI will report. Then check in FSI.

Core

  1. let rec f n = match n with 0 -> "" | n -> "*" + f (n - 1)
  2. let g x y = x * y + 0.5
  3. let h a b = if a then b else b + 1
  4. let k x = x
  5. let pairUp x y = y
  6. let apply f x = f x

Practice

  1. let compose f g x = g (f x)
  2. let m s n = String.replicate n s, given that String.replicate has type int -> string -> string

Stretch

  1. let rec loop n = loop (n + 1). The result type is surprising. Why?
  2. let weird x = failwith "no"
TipAnswers
  1. f: n: int -> string
  2. g: x: float -> y: float -> float. + 0.5 makes x * y a float, so both x and y are floats.
  3. h: a: bool -> b: int -> int. a is an if condition.
  4. k: x: 'a -> 'a
  5. pairUp: x: 'a -> y: 'b -> 'b
  6. apply: f: ('a -> 'b) -> x: 'a -> 'b. f is applied to x, so f is a function whose argument type is x’s type; nothing else is known, so both types stay generic.
  7. compose: f: ('a -> 'b) -> g: ('b -> 'c) -> x: 'a -> 'c. f’s result is passed to g, so they must agree ('b).
  8. m: s: string -> n: int -> string
  9. loop: n: int -> 'a. The function never returns, so nothing in the body says what it returns. The result type has no clues, so it stays generic. (A function that “returns any type you like” is a hint that it never returns normally.)
  10. weird: x: 'a -> 'b. failwith stops the program instead of returning, so, like loop, it can pretend to return any type. That’s why failwith "TODO" fits in any function body in the labs.

F. Write a function with this type

Write any function that FSI reports with exactly this type (parameter names don’t matter). There are many correct answers.

Practice

  1. int -> bool
  2. string -> int -> string
  3. int -> int -> bool

Stretch

  1. 'a -> int
  2. (int -> 'a) -> 'a
  3. 'a -> 'a -> 'a
TipSample answers 
let isPositive n = n > 0                      // int -> bool
let indent (s: string) n = String.replicate n " " + s   // string -> int -> string
let divides d n = n % d = 0                   // int -> int -> bool
let alwaysOne _ = 1                           // 'a -> int
let atZero f = f 0                            // (int -> 'a) -> 'a
let either x y = if true then x else y        // 'a -> 'a -> 'a

A trap in question 2: let label (s: string) n = s + string n has type string -> 'a -> string, not string -> int -> string. The function string accepts a value of any type, so it gives no clue about n. To make n an int, use it where only an int fits, as String.replicate does, or annotate it: (n: int).

Question 6 is the hardest: both parameters must have the same type, and the result too. Returning one of them from an if forces that, because both branches must have the same type.

G. Partial application

Core

  1. let laugh = repeat "ha". What is the type of laugh? What is laugh 3?
  2. What is the type of power 10.0? What is (power 10.0) 3?
  3. What does FSI report for let f = add?

Practice

  1. Using power and partial application, you can easily make “powers of 3”. Can you make “the cube of a number” the same way? Why not, and what would you change?

Stretch

  1. What is twice twice (add 1) 0? Work it out by substitution before trying it.
TipAnswers

  1. laugh: (int -> string), and laugh 3 = "hahaha".

  2. power 10.0: (int -> float), and (power 10.0) 3 = 1000.0.

  3. val f: (int -> int -> int). f is just another name for the same function.

  4. No: partial application fixes the first parameters, and power’s first parameter is the base. To fix the exponent, it would have to come first: with let rec power' n x = …, the cube would be power' 3. (You can also write fun x -> power x 3, which is Week 5’s topic.)

  5. 4. twice twice (add 1) means twice (twice (add 1)): “do (add 1) twice”, done twice, which is add 1 four times.

    twice twice (add 1) 0 = twice (twice (add 1)) 0
                      = (twice (add 1)) ((twice (add 1)) 0)
                      = (twice (add 1)) 2
                      = 4
