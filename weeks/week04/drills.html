Week 4 · Drills

Modeling Data: Records, Unions, and Option

Core for everyone, Practice for fluency, Stretch for a challenge. Work on paper first, then check in FSI. From this week on, one more check belongs in every answer: does every match handle every case? An FS0025 warning means the answer is wrong.

Unless a question says otherwise, use these definitions:

type Article = { Name: string; Price: int }

type Shape =
    | Circle of radius: float
    | Rectangle of width: float * height: float

type Light =
    | Red
    | Amber
    | Green

type Month =
    | January | February | March | April | May | June
    | July | August | September | October | November | December

A. Predict the response

Give the type and value, or error with a one-line reason. Assume let tea = { Name = "tea"; Price = 45 } has been entered.

Core

  1. { Name = "tea"; Price = 45 };;
  2. { tea with Price = 50 };;
  3. tea.Price + 5;;
  4. Circle 2.0;;
  5. Some "a";;
  6. [Some 1; None];;
  7. Some 3 + 1;;

Practice

  1. Some (Some 3);;
  2. Rectangle 3.0;;
  3. Some 3 = Some 3;;
  4. { Name = "tea" };;

Stretch

  1. [Circle 1.0; Some 2];;
  2. let bad r = r.Price;;. In Week 2, let len s = s.Length needed an annotation. Does this one? Why?
TipAnswers
  1. val it: Article = { Name = "tea"; Price = 45 }. F# recognises the record type from the field names.
  2. val it: Article = { Name = "tea"; Price = 50 }: a new record; tea is unchanged.
  3. val it: int = 50
  4. val it: Shape = Circle 2.0
  5. val it: string option = Some "a"
  6. val it: int option list = [Some 1; None]: None fits in, because it is a value of every option type.
  7. Error: The type 'int' does not match the type 'int option'. You can’t do arithmetic on a value that might not be there; match first.
  8. val it: int option option = Some (Some 3): an option of an option. It is legal, and occasionally useful: “we know there is an answer, and the answer is ‘maybe 3’”.
  9. Error: Rectangle needs a float * float, a width and a height.
  10. val it: bool = true. Options, like records and tuples, are compared by content.
  11. Error FS0764: No assignment given for field 'Price'. A record needs every field.
  12. Error: a list’s elements must all have the same type; Circle 1.0 is a Shape and Some 2 an int option.
  13. It works: val bad: r: Article -> int. F# knows the names of record fields, so .Price tells it the type is Article. .Length is a method or property of a .NET class, which F# can only look up once it knows the type. (If two records had a Price field, F# would pick the last one defined, the pitfall from the notes.)

B. Count the values

Using |A \mathbin{*} B| = |A| \times |B| and “a union adds up its cases”, how many values does each type have?

Core

  1. bool * bool
  2. Light option
  3. Month * bool
  4. bool option option

Practice

  1. { IsOpen: bool; Day: Month }
  2. type Coin = Heads | Tails paired with Light: Coin * Light
  3. type Answer = Yes | No | Maybe of bool

Stretch

  1. A function type bool -> bool. List all of them.
  2. Light -> bool
TipAnswers
  1. 2 \times 2 = 4
  2. 3 + 1 = 4: the three lights, plus None.
  3. 12 \times 2 = 24
  4. (2 + 1) + 1 = 4: None, Some None, Some (Some true), Some (Some false).
  5. 2 \times 12 = 24: a record counts like a tuple.
  6. 2 \times 3 = 6
  7. 1 + 1 + 2 = 4: Yes, No, Maybe true, Maybe false.
  8. 2^2 = 4: fun b -> b, fun b -> not b, fun _ -> true, fun _ -> false.
  9. 2^3 = 8: one bool answer for each of the three lights. (See the notes’ “Counting function types” box.)

C. Design a type

Write the F# type definitions. There is more than one good answer; aim for types without impossible values.

Core

  1. A playing card: a suit (clubs, diamonds, hearts, spades) and a rank (2–10, jack, queen, king, ace).
  2. A temperature that is either in Celsius or in Fahrenheit.
  3. A student with an ID, a name, and possibly a nickname.

Practice

  1. A delivery that is ordered, shipped (with a tracking ID), delivered (with a tracking ID and a date), or cancelled (with a reason).

  2. Someone proposes this instead:

    type DeliveryR =
    { IsShipped: bool
      IsDelivered: bool
      IsCancelled: bool
      TrackingId: string option
      Reason: string option }

    Give three values of this type that make no sense. How many combinations do the three bools alone allow, and how many of them are real states?

Stretch

  1. In your card type, Number 1 and Number 42 are probably possible. Is that a problem? How could you prevent it? (Hint: count the values of your Rank, and compare with 13.)
TipSample answers 
type Suit =
    | Clubs
    | Diamonds
    | Hearts
    | Spades

type Rank =
    | Number of int          // 2 to 10
    | Jack
    | Queen
    | King
    | Ace

type Card = { Rank: Rank; Suit: Suit }

type Temperature =
    | Celsius of float
    | Fahrenheit of float

type Student = { Id: string; Name: string; Nickname: string option }
type Delivery =
    | Ordered
    | Shipped of trackingId: string
    | Delivered of trackingId: string * date: string
    | Cancelled of reason: string

  1. Nonsense values include: delivered but not shipped; shipped and cancelled; delivered with no tracking ID; cancelled with no reason; a reason on a delivery that wasn’t cancelled. The three bools allow 2^3 = 8 combinations, but only four states are real (ordered, shipped, delivered, cancelled), and the options add even more nonsense. The union has exactly the four states, and each carries exactly its own data.

  2. With Number of int, Rank has about four billion values, but only 13 are real ranks. Every function must then worry about Number 42. One fix is to list all the ranks as cases: Two | Three | … | Ten | Jack | Queen | King | Ace, exactly 13 values. It is more typing, but no invalid rank can exist. Another fix, a smart constructor that checks the number once, is part of Week 9.

D. Functions on unions and records

Every match must be complete, with no FS0025.

Core

  1. perimeter for Shape.
  2. toCelsius for your Temperature type: C = (F - 32) \times 5 / 9.
  3. isRed for a card: diamonds and hearts are red.

Practice

  1. quarter : Month -> int: January–March is 1, and so on. Use or-patterns.
  2. rankValue for blackjack: number cards count their number, jack/queen/king count 10, an ace 11.
  3. trackingId : Delivery -> string option.
TipAnswers 
let perimeter shape =
    match shape with
    | Circle r -> 2.0 * System.Math.PI * r
    | Rectangle (w, h) -> 2.0 * (w + h)

let toCelsius t =
    match t with
    | Celsius c -> c
    | Fahrenheit f -> (f - 32.0) * 5.0 / 9.0

let isRed card =
    match card.Suit with
    | Diamonds | Hearts -> true
    | Clubs | Spades -> false
let quarter month =
    match month with
    | January | February | March -> 1
    | April | May | June -> 2
    | July | August | September -> 3
    | October | November | December -> 4

let rankValue rank =
    match rank with
    | Number n -> n
    | Jack | Queen | King -> 10
    | Ace -> 11

let trackingId delivery =
    match delivery with
    | Shipped id | Delivered (id, _) -> Some id
    | Ordered | Cancelled _ -> None

In trackingId, the or-pattern Shipped id | Delivered (id, _) works because both alternatives bind the same name id, of the same type.

E. Option

Core

  1. safeDiv a b: None when b is 0, otherwise Some (a / b).
  2. tryFirstEven: the first even number in a list, if any.
  3. tryMaximum: Week 3’s maximum, but with an option instead of failwith. tryMaximum [] = None.

Practice

  1. digitValue : char -> int option: digitValue '7' = Some 7, digitValue 'x' = None. (Hint: int '7' - int '0' is 7.)
  2. firstSome : 'a option list -> 'a option: the first value that is there.
  3. values : 'a option list -> 'a list: keep the values, drop the Nones. What shape is this?

Stretch

  1. tryNth n xs: the element at position n, if the list is long enough.
  2. allSome : 'a option list -> 'a list option: Some of all the values if every element is Some, otherwise None. allSome [Some 1; Some 2] = Some [1; 2], allSome [Some 1; None] = None.
TipAnswers 
let safeDiv a b =
    match b with
    | 0 -> None
    | b -> Some (a / b)

let rec tryFirstEven xs =
    match xs with
    | [] -> None
    | x :: _ when x % 2 = 0 -> Some x
    | _ :: rest -> tryFirstEven rest

let rec tryMaximum xs =
    match xs with
    | [] -> None
    | x :: rest ->
        match tryMaximum rest with
        | Some m -> Some (max x m)
        | None -> Some x               // rest was empty: x is the only one

In tryMaximum, the recursive result is itself an option: None means the rest was empty, so x is the maximum.

let digitValue c =
    match c with
    | c when c >= '0' && c <= '9' -> Some (int c - int '0')
    | _ -> None

let rec firstSome xs =
    match xs with
    | [] -> None
    | Some x :: _ -> Some x
    | None :: rest -> firstSome rest

let rec values xs =
    match xs with
    | [] -> []
    | Some x :: rest -> x :: values rest
    | None :: rest -> values rest
  1. values is keep some combined with transform each: it keeps the Somes and unwraps them.
let rec tryNth n xs =
    match n, xs with
    | _, [] -> None
    | 0, x :: _ -> Some x
    | n, _ :: rest -> tryNth (n - 1) rest

let rec allSome xs =
    match xs with
    | [] -> Some []
    | None :: _ -> None
    | Some x :: rest ->
        match allSome rest with
        | Some ys -> Some (x :: ys)
        | None -> None
  1. allSome has to match on the recursive result, and every step that might fail makes the code one level deeper. Week 8 has a neat way to flatten exactly this kind of nesting.

F. Find the bug

Core

  1. A new case | Flashing is added to Light. This function compiled before. What happens now, and why is that good news?

    let next light =
    match light with
    | Red -> Green
    | Green -> Amber
    | Amber -> Red
  2. let rec indexOf x xs =
    match xs with
    | [] -> -1
    | y :: _ when y = x -> 0
    | _ :: rest -> 1 + indexOf x rest

    What is indexOf 9 [1; 2; 3]? What should the type have been?

Practice

  1. This compiles with no warning at all. Why is it still a risk when Flashing is added?

    let describeLight light =
    match light with
    | Red -> "stop"
    | Green -> "go"
    | _ -> "stop"

  2. Someone “handles” an option like this. What is wrong with it?

    let priceOf item table =
    match tryLookup item table with
    | Some p -> p
    | None -> 0

Stretch

  1. With both Point and Vector defined (as in the notes), why does let len v = sqrt (v.X * v.X + v.Y * v.Y) only accept Vectors? Fix it so it works on Points.
TipAnswers
  1. Warning FS0025, naming Flashing as the missing case. Good news: the compiler has found a place you need to update, before any user sees a crash.
  2. 1 + (1 + (1 + -1)) = 2, which looks like a real position! The -1 “magic value” gets mixed into the arithmetic. With int option, it would be None. (This is the Week 3 lab’s indexOf, which had to check for -1 carefully; with an option, the type does the checking.)
  3. The wildcard _ catches Amber and every future case, so Flashing silently becomes "stop", with no warning. Wildcards turn off the completeness check. Prefer listing the cases, so that new ones are reported.
  4. It turns None back into a magic value: a missing item now costs 0 baht, and nobody notices. withDefault is right when there is a sensible default. For prices there isn’t one, so priceOf should return the option (or its caller should decide what to do).
  5. F# picks the record type defined last with fields X and Y, which is Vector. Annotate: let len (v: Point) = ….

G. Your own list type (Stretch)

Using MyList<'a> from the notes:

  1. fromList : 'a list -> MyList<'a>
  2. toList : MyList<'a> -> 'a list
  3. mySum : MyList<int> -> int. Compare it with Week 3’s sum.
TipAnswers 
type MyList<'a> =
    | Empty
    | Cons of 'a * MyList<'a>

let rec fromList xs =
    match xs with
    | [] -> Empty
    | x :: rest -> Cons (x, fromList rest)

let rec toList xs =
    match xs with
    | Empty -> []
    | Cons (x, rest) -> x :: toList rest

let rec mySum xs =
    match xs with
    | Empty -> 0
    | Cons (x, rest) -> x + mySum rest

mySum is Week 3’s sum with [] renamed Empty and x :: rest renamed Cons (x, rest). The recipe was always “one rule per case of the type”.
