Predict: coming from Python

In Python, [1, 2] is a list of two numbers. In F#:

> [1, 2];;
val it: (int * int) list = [(1, 2)]

A list with one element: the pair (1, 2). No error, no warning.

In F#, the comma always makes a tuple. Lists use ;.

Ask for the type before revealing. Many will say “int list”. Emphasise: always read the type FSI reports.

Both together

let prices = [("coffee", 55); ("tea", 45); ("cake", 80)]

(string * int) list: commas inside each pair, semicolons between pairs.

One Python intuition does carry over: the comma, not the parentheses, makes a tuple.

> let p = 1, 2;;
val p: int * int = (1, 2)

Lists

Building lists

let empty : int list = []
let digits = [0 .. 9]              // a range
let evensDown = [10 .. -2 .. 0]    // [10; 8; 6; 4; 2; 0]
let nothing = [5 .. 1]             // []: an empty range
> [1; "two"];;
error FS0001: All elements of a list must be implicitly convertible
to the type of the first element, which here is 'int'.

What a list really is

Every list is either

  • the empty list [], or
  • an element in front of a list: x :: rest (the head and the tail)
let xs = [2; 3]
let ys = 1 :: xs            // [1; 2; 3]; xs unchanged
let same = 1 :: 2 :: 3 :: []   // what [1; 2; 3] means

:: shares, it doesn’t copy

Safe because lists are immutable (Week 1). And cheap: one new cell, however long xs is.

List patterns

Pattern Matches For [4; 5; 6]
[] empty list no
x :: rest non-empty x ↦ 4, rest ↦ [5; 6]
_ :: rest non-empty, ignore head rest ↦ [5; 6]
[x] exactly one element no
x :: y :: rest at least two x ↦ 4, y ↦ 5, rest ↦ [6]

Forget [], and F# tells you: FS0025 … the value '[]' may indicate a case not covered.

The recipe, for lists

The list gives you the cases

  1. Type — usually 'a list -> …
  2. Base case — the empty list []
  3. Recursive case — x :: rest: trust f rest, combine with x
  4. Check — trace a short list. Getting smaller is free: rest is shorter.

Problem: the length of a list

length [7; 8; 9] = 3, length [] = 0

Your turn. Type? Base case? Recursive case?

length: the recipe

  1. Type — 'a list -> int: any element type
  2. Base case — length [] = 0
  3. Recursive case — one more than length rest
  4. Check — length [7; 8] = 1 + (1 + 0) = 2
let rec length xs =
    match xs with
    | [] -> 0
    | _ :: rest -> 1 + length rest

It never looks at the elements (_), so it is generic.

sum: same recipe, another step

sum [1; 2; 3] = 6

Before the code: what is the base case? What is the recursive step?

  • Base case — sum [] = 0
  • Recursive step — add x to the trusted sum rest
let rec sum xs =
    match xs with
    | [] -> 0
    | x :: rest -> x + sum rest
sum [1; 2; 3] = 1 + sum [2; 3]
              = 1 + (2 + sum [3])
              = 1 + (2 + (3 + sum []))
              = 1 + (2 + (3 + 0)) = 6

Give students a moment at “Before the code”. Ask what the base case should be, and why it is 0 and not 1.

append: now the base case changes

append [1; 2] [3; 4] = [1; 2; 3; 4]

Before the code: there are two lists. Which one do you take apart? What is append [] ys?

  • Base case — append [] ys = ys: not []!
  • Recursive step — put x in front of the trusted append rest ys
let rec append xs ys =
    match xs with
    | [] -> ys
    | x :: rest -> x :: append rest ys
append [1; 2] [3; 4] = 1 :: append [2] [3; 4]
                     = 1 :: (2 :: append [] [3; 4])
                     = [1; 2; 3; 4]

Point out: only the first list is taken apart; the second is shared. Built in as @.

isMember: now the answer is a bool

isMember 3 [1; 2; 3] = true, isMember 9 [1; 2] = false

Before the code: base case? Recursive step? Does it need to look at the whole list?

  • Base case — isMember x [] = false: nothing is in the empty list
  • Recursive step — x is the head, or it is in the trusted isMember x rest
let rec isMember x xs =
    match xs with
    | [] -> false
    | y :: rest -> x = y || isMember x rest

|| stops as soon as the answer is true.

Same recipe, different steps

Function Base case Recursive step
length 0 1 + length rest
sum 0 x + sum rest
append ys x :: append rest ys
isMember false x = y || isMember x rest

The recipe is always the same. The thinking is in these two columns: the answer for [], and how to build the answer from x and the trusted f rest.

when 'a: equality

val isMember: x: 'a -> xs: 'a list -> bool when 'a: equality

Any type whose values can be compared with =. Not functions:

> f = f;;
error FS0001: The type 'int -> int' does not support the 'equality'
constraint because it is a function type

Recursion shapes

Problem: double every element

doubleAll [1; 2; 3] = [2; 4; 6]

Your turn. Base case? Recursive case?

Shape 1: transform each

let rec doubleAll xs =
    match xs with
    | [] -> []
    | x :: rest -> 2 * x :: doubleAll rest
let rec lengths (words: string list) =
    match words with
    | [] -> []
    | w :: rest -> w.Length :: lengths rest

Always [] -> [] and (something with x) :: f rest. Only the something changes.

Problem: keep the even numbers

evens [1; 2; 3; 4; 6] = [2; 4; 6]

Your turn. How many recursive cases do you need?

Shape 2: keep some

let rec evens xs =
    match xs with
    | [] -> []
    | x :: rest when x % 2 = 0 -> x :: evens rest
    | _ :: rest -> evens rest

Two recursive cases: keep x (x :: f rest) or drop it (f rest). A guard decides.

let rec removeAll y xs =
    match xs with
    | [] -> []
    | x :: rest when x = y -> removeAll y rest
    | x :: rest -> x :: removeAll y rest

Problem: the largest element

maximum [3; 9; 2] = 9

Your turn. What is the base case? What is maximum []?

Someone will propose [] -> 0. Ask them to try maximum [-3; -1].

Shape 3: combine all

let rec maximum xs =
    match xs with
    | [] -> failwith "maximum: empty list"
    | [x] -> x
    | x :: rest -> max x (maximum rest)

The maximum of no numbers doesn’t exist: base case [x], and [] is an error.

sum, length, product too: the base case is the answer for no elements (0, 0, 1).

Problem: are all elements positive?

allPositive [1; 2] = true, allPositive [1; -2; 3] = false

Your turn. And: does your version look at the 3?

Shape 4: stop early

let rec allPositive xs =
    match xs with
    | [] -> true
    | x :: rest -> x > 0 && allPositive rest

&& doesn’t evaluate its right side when the left is false (Week 1).

So allPositive [1; -2; 3; 4; 5] stops at -2. isMember has the same shape, with ||.

Problem: say everything twice

stutter [1; 2] = [1; 1; 2; 2]

concat [[1]; []; [2; 3]] = [1; 2; 3]

Your turn. How many elements does each x contribute?

Shape 5: each to many

let rec stutter xs =
    match xs with
    | [] -> []
    | x :: rest -> x :: x :: stutter rest
let rec concat xss =
    match xss with
    | [] -> []
    | xs :: rest -> append xs (concat rest)

Each element contributes zero, one, or several elements. Other languages call this shape flatMap. Remember the name.

Why the shapes matter

Transform each

| x :: rest ->
    2 * x :: f rest
| x :: rest ->
    w.Length :: f rest

Keep some

| x :: rest when x % 2 = 0 -> …
| x :: rest when x = y -> …

In each shape, everything is the same except one small piece.

Week 5: each shape becomes one function; the piece becomes a parameter. You will recognise them all.

Lists and tuples together

Problem: pair up two lists

zip [1; 2; 3] ["a"; "b"] = [(1, "a"); (2, "b")]

Your turn. You need to look at both lists at once. How?

Matching on two values

let rec zip xs ys =
    match xs, ys with
    | x :: xs', y :: ys' -> (x, y) :: zip xs' ys'
    | _ -> []                     // either one ran out

match xs, ys with matches the pair (xs, ys): each rule has a pair of patterns.

val zip: xs: 'a list -> ys: 'b list -> ('a * 'b) list

Problem: unzip

unzip [(1, "a"); (2, "b")] = ([1; 2], ["a"; "b"])

Your turn. Trust unzip rest. What does it give you, and what do you do with it?

Using the result of the recursive call

let rec unzip pairs =
    match pairs with
    | [] -> ([], [])
    | (x, y) :: rest ->
        let (xs, ys) = unzip rest     // trust it; take it apart
        (x :: xs, y :: ys)

Take the recursive result apart with a pattern, then build the answer.

let rec sumProd xs =
    match xs with
    | [] -> (0, 1)
    | x :: rest ->
        let (s, p) = sumProd rest
        (x + s, x * p)

A lookup table

let rec lookup key table =
    match table with
    | [] -> failwith ("lookup: no entry for " + key)
    | (k, v) :: _ when k = key -> v
    | _ :: rest -> lookup key rest

lookup "tea" prices = 45. The pattern (k, v) :: _ takes apart the first pair inside the list pattern.

failwith for a missing key; next week does better.

What things cost

Cheap and expensive

Operation Cost
x :: xs constant: one cell, xs shared
head constant
length xs walks the whole list
xs @ ys copies xs, shares ys
xs[i] walks i cells: lists aren’t arrays

Predict: naive reverse

let rec naiveRev xs =
    match xs with
    | [] -> []
    | x :: rest -> append (naiveRev rest) [x]
> naiveRev [1 .. 10000] |> List.length;;
Real: 00:00:00.771 ...

How long for 20,000?

> naiveRev [1 .. 20000] |> List.length;;
Real: 00:00:03.029 ...

Double the list, 4× the time. List.rev does a million in 0.05 s (Week 7).

Two lists at once

Problem: merge two sorted lists

merge [1; 4; 9] [2; 3; 10] = [1; 2; 3; 4; 9; 10]

Your turn. What if one list is empty? Otherwise, what goes first?

merge

let rec merge xs ys =
    match xs, ys with
    | [], ys -> ys
    | xs, [] -> xs
    | x :: xs', y :: ys' ->
        if x <= y then x :: merge xs' ys
        else y :: merge xs ys'

Each call removes one element from one of the lists, so it stops.

The lab combines merge with split into merge sort.

Text as a list of characters

let letters = List.ofSeq "level"   // a char list
let word = System.String.Concat ['o'; 'k']   // "ok"
let rec countChar c (cs: char list) =
    match cs with
    | [] -> 0
    | x :: rest when x = c -> 1 + countChar c rest
    | _ :: rest -> countChar c rest

Summary

  • ; separates list elements; , makes tuples. [1, 2] is one pair
  • Tuples: types with *; take apart with patterns
  • Lists: [] or x :: rest; :: is cheap and shares
  • Recipe: base [], recursive x :: rest trusting f rest
  • Five shapes: transform each, keep some, combine all, stop early, each to many
  • @ copies its first list; naive reverse is quadratic
