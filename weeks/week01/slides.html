Two ways to compute

Statement style: how

// Statement style: create a variable, then change it step by step.
let mutable total = 0
total <- total + 72
total <- total + 85
total <- total + 90
let mutable average = 0.0
average <- float total / 3.0

To know what average is, you replay the steps in order.

Expression style: what

// Expression style: say what the average IS.
let averageOf3 a b c = float (a + b + c) / 3.0
let myAverage = averageOf3 72 85 90
Imperative Functional
a program is statements that change state expressions that define values
a variable is a box whose contents change a name for a value that never changes
to understand it replay the steps replace names by their meaning

Values and bindings

Talking to FSI

> 2 * 3 + 4;;
val it: int = 10
  • val: here is a value
  • it: the name FSI gives the last result
  • int: its type
  • 10: its value

;; means “evaluate now”. It is only used in FSI, never in files.

let binds a name to a value

let price = 25 * 5
let newPrice = 2 * price
let isExpensive = newPrice > 500

The environment after these three lines:

[ price ↦ 125,   newPrice ↦ 250,   isExpensive ↦ false ]

No types written, all types known: type inference.

Predict: what does addTax 100 give?

> let rate = 7;;
> let addTax amount = amount + amount * rate / 100;;
> let rate = 10;;
> addTax 100;;
val it: int = 107

The second let made a new binding. It did not change the old one. This is called shadowing.

Give students 30 seconds and a show of hands: 107 or 110? Then mention that a script file rejects duplicate top-level names (“Duplicate definition”); FSI allows it because each entry is its own step.

Everything is an expression

if produces a value

let temperature = 34
let advice =
    if temperature > 30 then "Stay hydrated"
    else "Enjoy the weather"
let describe t =
    if t > 35 then "very hot"
    elif t > 30 then "hot"
    elif t > 20 then "pleasant"
    else "cool"

So: both branches need the same type, and the else is required.

The compiler says it for us

> if 3 > 2 then "yes";;

error FS0001: This 'if' expression is missing an 'else' branch.
Because 'if' is an expression, and not a statement, add an 'else'
branch which also returns a value of type 'string'.

A block’s value is its last expression

let totalWithVat price quantity =
    let subtotal = price * quantity   // local binding
    let vat = subtotal * 7 / 100      // Thai VAT: 7%
    subtotal + vat                    // the result
  • let lines are local: visible only below them
  • no return: the last line is the result
  • indentation decides what belongs to the body

But what about printfn?

If everything is an expression… what is printfn "Hello"?

It is an expression. Evaluating it:

  • produces the value (), of type unit
  • and prints, which is a side effect
> let greet name = printfn "Hello, %s!" name;;
val greet: name: string -> unit

Let students propose answers first. Someone usually says “printfn is a statement”; the FSI response shows it has a type and a value.

Two different properties

Means Guaranteed by F#?
Everything is an expression every construct has a value and a type yes, by design
Pure evaluating it does nothing but produce its value no, it’s our discipline

2 + 3 is pure. printfn "Hi" is not.

This course: build programs mostly from pure expressions, and keep effects few, visible, and at the edges.

Effects happen once, when evaluated, in order

let u = printfn "computing..."   // prints now, once
let v = u                        // u is just (), nothing is printed
let answer () =
    printfn "thinking..."        // evaluated first, for its effect
    printfn "almost there..."    // then this one
    42                           // the value of the whole block

Lines before the last run top to bottom for their effects, and their values are thrown away. -> unit in a type is a warning sign: expect an effect.

No mixing int and float

> 2 * 3.0;;
error FS0001: The type 'float' does not match the type 'int'

Convert explicitly, using the type’s name as a function:

let items = 3
let unitPrice = 19.5
let cost = float items * unitPrice   // float 3 is 3.0
let rounded = int 57.9               // truncates: 57

Mention the F# 6 nuance only if asked: an int is widened when a float is already expected (passing an argument to a float parameter). Operators never mix.

Functions

Defining and applying

let circleArea r = System.Math.PI * r * r
let area1 = circleArea 1.0
let area2 = circleArea 2.5
val circleArea: r: float -> float

Apply by writing the argument after the function, no parentheses needed.

Parentheses only group

let square x = x * x

let a1 = square 3 + 1        // (square 3) + 1 = 10
let a2 = square (3 + 1)      // square 4       = 16

Function application binds tighter than any operator.

With nothing to say otherwise, x * x assumes int, so square: x: int -> int.

Two parameters

let totalCost unitPrice quantity = unitPrice * float quantity
let order = totalCost 19.5 4
val totalCost: unitPrice: float -> quantity: int -> float

Not totalCost(19.5, 4)

(19.5, 4) is one value, a pair. Write totalCost 19.5 4.

Functions are values

let double = fun x -> 2 * x     // same as: let double x = 2 * x
let eight = (fun x -> 2 * x) 4  // apply it directly

fun x -> … is a function without a name, a lambda.

A function can be bound, passed, and returned like any value. That is Week 5.

Evaluation by substitution

The rules

  1. Name — replace it by the value it is bound to
  2. Arguments — evaluate them to values first
  3. Apply — take the body; replace each parameter by its argument
  4. Operator — compute it once both sides are values
  5. if — evaluate the condition; keep only the chosen branch
  6. Local let — evaluate it; replace the name in the lines below

We write ⇝ for “evaluates in one step to”.

Tracing sumOfSquares 3 (1 + 1)

let square x = x * x
let sumOfSquares a b = square a + square b
   sumOfSquares 3 (1 + 1)
⇝ sumOfSquares 3 2              (2) arguments first
⇝ square 3 + square 2           (3) a ↦ 3, b ↦ 2
⇝ (3 * 3) + square 2            (3) x ↦ 3
⇝ 9 + square 2                  (4)
⇝ 9 + (2 * 2)                   (3) x ↦ 2
⇝ 9 + 4                         (4)
⇝ 13                            (4)

Every line is an F# expression. Every line has the same value.

Each click reveals one step. Before each click, ask which rule applies next.

Tracing with if

let shippingFee weight =
    if weight <= 1 then 40
    elif weight <= 5 then 40 + (weight - 1) * 15
    else 100 + (weight - 5) * 10
   shippingFee 3
⇝ if 3 <= 1 then 40                               (3)
   elif 3 <= 5 then 40 + (3 - 1) * 15
   else 100 + (3 - 5) * 10
⇝ if false then 40 elif 3 <= 5 then …             (4)
⇝ if 3 <= 5 then 40 + (3 - 1) * 15 else …         (5)
⇝ if true then 40 + (3 - 1) * 15 else …           (4)
⇝ 40 + (3 - 1) * 15                               (5)
⇝ 40 + 2 * 15  ⇝  40 + 30                         (4)
⇝ 70                                              (4)

Point out that the unchosen branches are never evaluated.

Why this works

Anywhere a name appears, you can replace it by its definition. Anywhere an expression appears, you can replace it by its value. The meaning does not change.

This property is called referential transparency.

It lets you understand each piece of a program on its own, the way you simplify one part of an equation.

When substitution breaks

let mutable counter = 0
let nextId () =
    counter <- counter + 1
    counter

let x1 = nextId () + nextId ()   // 1 + 2 = 3
let x2 = 2 * nextId ()           // 2 * 3 = 6

In mathematics, f(x) + f(x) = 2\,f(x) for every f and x.

Here, with x = (): 3 ≠ 6.

nextId () has no fixed value. To understand it, you are back to replaying steps.

Every side effect does this: printfn "Hi" has value (), but replacing it by () removes the output. DateTime.Now differs each time you read it.

Immutability

Two names, one array

let scores = [| 70; 80; 90 |]   // an array: mutable
let backup = scores             // NOT a copy!
scores[0] <- 0
let surprise = backup[0]        // 0: backup changed too

let backup = scores gives the same array a second name. This is aliasing.

If nothing can change, sharing is always safe: pass it anywhere, store it, share it between threads (Week 12).

Mutation: available, but explicit

  • F# values are immutable by default; “change” means compute a new value
  • let mutable and <- exist, for when you can say why
> let mutable x = 1;;
> x = 2;;
val it: bool = false

= compares. <- assigns.

Beyond F#

Value-producing if Non-reassignable binding
Rust let a = if t > 30 { "hot" } else { "ok" }; let (vs let mut)
Kotlin val a = if (t > 30) "hot" else "ok" val
TypeScript const a = t > 30 ? "hot" : "ok"; const, binding only!
Python a = "hot" if t > 30 else "ok" none (convention)

Habit to keep: default to the non-reassignable form; make conditionals produce values; treat “update” as “compute a new value”.

Rewrite without mutable

let mutable msg = "Result: "
if score >= 50 then msg <- msg + "pass" else msg <- msg + "fail"
msg <- msg + $" ({score})"
let msgExpression score =
    let verdict = if score >= 50 then "pass" else "fail"
    $"Result: {verdict} ({score})"

Naming the intermediate value is often the cleanest rewrite.

Summary

  • Programs are expressions; functions map values to values
  • let binds; bindings never change (shadowing makes a new one)
  • if is an expression: same type in both branches, else required
  • Apply with spaces: f x y; parentheses only group
  • No mutation ⇒ evaluate by substitution (referential transparency)
  • Immutable values can be shared safely
