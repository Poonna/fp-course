Week 1 · Drills

Programs as Expressions

Work through these on paper first, then check in FSI. The point is to build the habit of predicting what F# will do. Being wrong and finding out why is exactly the learning. Answers are hidden under each section; open them only after you have committed to an answer.

A. Predict the FSI response

For each input, write what FSI replies: the type and value, or error together with a one-line reason. Do not run them first.

  1. 7 / 2;;
  2. 7.0 / 2.0;;
  3. 7 % 2;;
  4. "7" + "2";;
  5. "7" + 2;;
  6. sqrt 16;;
  7. sqrt 16.0;;
  8. float 7 / 2.0;;
  9. int 3.99;;
  10. string 42 + "!";;
  11. let y = 10;; followed by y = 11;;
  12. not (3 < 2) && "abc" < "abd";;
  13. (fun x -> x * 3) 5;;
  14. if 2 > 1 then 10 else "twenty";;
TipAnswers
  1. val it: int = 3, integer division drops the remainder.
  2. val it: float = 3.5
  3. val it: int = 1, the remainder.
  4. val it: string = "72", + joins strings.
  5. Error: int does not match string. F# does not convert 2 to "2" for you.
  6. Error: int does not support Sqrt. sqrt needs a float.
  7. val it: float = 4.0
  8. val it: float = 3.5. float 7 is 7.0, and function application binds tighter than /.
  9. val it: int = 3, conversion truncates; it does not round.
  10. val it: string = "42!"
  11. val y: int = 10, then val it: bool = false. = compares; it never assigns.
  12. val it: bool = true. Strings compare alphabetically, and "abc" comes before "abd".
  13. val it: int = 15
  14. Error: all branches of an if must have the same type.

B. Read the type

Without running them, write the type FSI will report for each function. Then explain in words what the type tells you.

let f x = x + 1
let g x = x + 1.0
let h x = x + "!"
let k x y = x * y + 1
let greet name = printfn "Hello, %s" name
let describe n = if n % 2 = 0 then "even" else "odd"
TipAnswers
  • f: x: int -> int, because 1 is an int, so x must be one too.
  • g: x: float -> float, because 1.0 is a float.
  • h: x: string -> string, because "!" is a string, so + here means joining strings.
  • k: x: int -> y: int -> int: two int parameters, int result.
  • greet: name: string -> unit. It returns nothing interesting; it is used for its side effect (printing).
  • describe: n: int -> string. % and = 0 force n to be an int, and both branches are strings.

In every case F# found the type from how the parameter is used. Week 2 looks at this closely.

C. Trace by hand

Use these definitions:

let square x = x * x
let rectangleArea width height = width * height

let shippingFee weight =
    if weight <= 1 then 40
    elif weight <= 5 then 40 + (weight - 1) * 15
    else 100 + (weight - 5) * 10

let priceAfterDiscount price qty =
    let subtotal = price * qty
    let discount = if subtotal > 1000 then subtotal / 10 else 0
    subtotal - discount

Evaluate each expression step by step using the substitution rules from the notes (number each step with the rule you used), until you reach a value.

  1. rectangleArea 2 (1 + 2)
  2. square (square 2)
  3. shippingFee 7
  4. priceAfterDiscount 300 4. Then, without a full trace, what is priceAfterDiscount 300 3, and why?
TipAnswers 
1.   rectangleArea 2 (1 + 2)
   ⇝ rectangleArea 2 3             (2)
   ⇝ 2 * 3                         (3) width ↦ 2, height ↦ 3
   ⇝ 6                             (4)

2.   square (square 2)
   ⇝ square (2 * 2)                (2),(3) the argument first: x ↦ 2
   ⇝ square 4                      (4)
   ⇝ 4 * 4                         (3) x ↦ 4
   ⇝ 16                            (4)

3.   shippingFee 7
   ⇝ if 7 <= 1 then 40 elif 7 <= 5 then … else 100 + (7 - 5) * 10    (3)
   ⇝ if false then 40 elif 7 <= 5 then … else …                      (4)
   ⇝ if 7 <= 5 then 40 + (7 - 1) * 15 else 100 + (7 - 5) * 10        (5)
   ⇝ if false then … else 100 + (7 - 5) * 10                         (4)
   ⇝ 100 + (7 - 5) * 10                                              (5)
   ⇝ 100 + 2 * 10  ⇝  100 + 20  ⇝  120                               (4)

4.   priceAfterDiscount 300 4
   ⇝ let subtotal = 300 * 4                                   (3)
     let discount = if subtotal > 1000 then subtotal / 10 else 0
     subtotal - discount
   ⇝ let discount = if 1200 > 1000 then 1200 / 10 else 0      (6) subtotal ↦ 1200
     1200 - discount
   ⇝ let discount = 1200 / 10                                 (4),(5)
     1200 - discount
   ⇝ 1200 - 120                                               (6) discount ↦ 120
   ⇝ 1080                                                     (4)

For priceAfterDiscount 300 3: the subtotal is 900, which is not above 1000, so the if chooses 0 and the result is 900.

Note in trace 2 that the inner square 2 is evaluated before the outer square is applied. That is rule (2): arguments first.

D. From statements to expressions

Each snippet below is written in statement style, using a mutable variable. Rewrite it as a single binding with no mutable and no <-. Then answer the question.

D1.

let mutable fee = 0
if isMember then fee <- 50 else fee <- 100

D2.

let mutable msg = "Result: "
if score >= 50 then msg <- msg + "pass" else msg <- msg + "fail"
msg <- msg + $" ({score})"

D3.

let mutable category = ""
if bmi < 18.5 then category <- "under"
if bmi >= 18.5 && bmi < 25.0 then category <- "normal"
if bmi >= 25.0 then category <- "over"

Question: The statement version needs a placeholder "". What goes wrong if one of the three conditions has a typo, say bmi > 25.0 instead of bmi >= 25.0? Could the same mistake happen silently in your expression version?

TipAnswers 
let feeExpression isMember = if isMember then 50 else 100
let msgExpression score =
    let verdict = if score >= 50 then "pass" else "fail"
    $"Result: {verdict} ({score})"

Naming the intermediate value (verdict) is often the cleanest way to turn a sequence of updates into expressions.

let categoryExpression bmi =
    if bmi < 18.5 then "under"
    elif bmi < 25.0 then "normal"
    else "over"

With the typo, a BMI of exactly 25.0 matches none of the conditions, so category stays "". Nothing warns you, and the empty string escapes into the rest of the program. In the expression version, the final else covers every remaining case, and F# requires it. Because each branch only has to handle what the earlier ones didn’t, overlapping or missing ranges are much harder to write by accident.

E. Can you substitute?

For each pair, say whether the two versions are guaranteed to behave the same, and why. Assume square, shippingFee, and greet are as defined in the notes, and nextId is the counter function from the notes.

  1. square 5 + square 5 and 2 * square 5

  2. nextId () + nextId () and 2 * nextId ()

  3. shippingFee 3 + shippingFee 3 and

    let t = shippingFee 3
t + t

  4. Calling greet "Ann" twice in a row, and

    let g = greet "Ann"
g
g

  5. System.DateTime.Now - System.DateTime.Now and

    let t = System.DateTime.Now
t - t
TipAnswers
  1. Same. square 5 always means 25, so both are 50.
  2. Different. nextId () changes a mutable variable, so each call gives a different result (3 vs 6, starting from 0).
  3. Same. shippingFee only computes; binding its result to a name and using it twice changes nothing.
  4. Different, even though both produce the value (). The first prints Hello, Ann! twice. In the second, greet "Ann" runs once, when g is bound; after that, g is just the value () and mentioning it prints nothing.
  5. Different. The second is always exactly zero. In the first, the clock is read twice, so the difference may be a tiny non-zero time. Or it may be zero, which is worse: the bug only shows up occasionally. Reading the clock is a side effect, even though nothing is printed or changed.

The pattern: substitution is safe for pure expressions, the ones that only compute. As soon as an expression does something (changes a variable, prints, reads input or the clock), how many times it runs, and when, starts to matter.

F. Spot and fix

Each line has a problem. Say what F# will report (or what goes wrong), then fix it.

  1. let floor = rectangleArea(4, 3)
  2. let total = 3 * 19.5
  3. let sign x = if x > 0 then "positive"
  4. let mutable counter = 5 followed by counter = 6 (the intent is to set it to 6)
TipAnswers
  1. (4, 3) is one value, a pair (type int * int), but rectangleArea expects two separate ints. It is a type error.
  2. int and float can’t be mixed in arithmetic. It is a type error.
  3. The if produces a string, so it needs an else branch. It is an error.
  4. There is no error, but counter = 6 compares and evaluates to false, so counter stays 5. At the top level of a script this happens silently. Inside a function body, F# warns you (FS0020: The result of this equality expression has type 'bool' and is implicitly discarded… If you intended to mutate a value, then use the '<-' operator).
let f1 = rectangleArea 4 3              // F1
let f2 = float 3 * 19.5                 // F2
let sign x = if x > 0 then "positive" else "not positive"   // F3
let mutable counter = 5
counter <- 6                            // F4
